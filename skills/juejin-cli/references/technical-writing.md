# 技术文章整理与发布配置

本指南参考用户提供的 [CatBuddy 掘金专栏写作规范](https://github.com/Ganzhib/catbuddy/blob/book/book/00-WRITING-GUIDE.md)，提炼为适用于不同项目的写作流程；不继承 CatBuddy 的专栏名称和编号。

## 先识别文章类型

| 类型 | 推荐结构 | 必须有的证据 |
| --- | --- | --- |
| 架构设计 | 具体问题 → 组件关系图 → 取舍 → 失败场景 | 对应源码路径、真实调用链 |
| 实操教程 | 使用目标 → 环境 → 最小步骤 → 预期结果 → 常见错误 | 可运行命令、实际输出或注明未验证 |
| 排障复盘 | 现象 → 复现 → 排查 → 根因 → 修复 → 回归 | 错误信息、复现条件、验证结果 |
| 经验总结 | 使用场景 → 观察 → 方法 → 适用范围 | 实例、限制，不编造性能数字 |

尊重原稿的有效结构，只整理影响理解的部分。每篇开头约 100 字交代项目和本文问题，让从搜索进入的读者也能读懂。一个小节围绕一个问题展开，先说遇到的具体困难，再解释方案和取舍。

架构文章优先用 1–2 张图说明组件或时间顺序；平台渲染能力未确认时可用短文本图，避免直接依赖 Mermaid 渲染。源码片段尽量不超过 20 行，之后说明输入、输出或它解决的具体问题。术语首次出现简要解释。结尾交代适用范围和未解决的问题，不虚构后续计划。

## 自动准备配置

1. 扫描用户指定目录；保留原稿，在专用发布目录生成整理后的 Markdown。不要将目录内无关笔记一起发布。
2. 根据文章内容写有信息量的标题和 50–100 字摘要；不把第一段机械截断当作摘要。
3. 先采用用户指定的分类、标签和专栏；缺少分类标签时通过 CLI 查询真实候选，按主题匹配，写入字符串 ID。不要猜测不存在的 ID。
4. 同一批文章使用用户指定的一个专栏。未知专栏时集中查询和确认一次，已有明确选择则直接复用。
5. 检查本地图片、代码块语言、链接和占位符；不添加未经实际验证的结果。文中区分已发布功能、本地开发功能与未来计划。
6. 已授权发布时，完成全量预检后执行；仅要求写作或草稿时停在相应阶段。

批量入口可用时（先查询 `schema article publish-directory --json`）：

```bash
juejin article publish-directory ./prepared --column COLUMN_ID --dry-run --json
juejin article publish-directory ./prepared --column COLUMN_ID --json
```

当前入口处理目录第一层的 `.md` 文件。`.juejin-batch.json` 保存进度，完成项跳过；未知写入须先查询 `history` 和远端，不能删除进度文件后盲目重跑。文章或配置改变时使用独立任务目录，先核对旧任务。此入口在 0.1.0 不可用，旧版本按文件执行草稿创建、更新与发布。
